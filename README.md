# EricCyclesABit

A personal Streamlit dashboard for tracking cycling goals against your real ride history — pulled from a Strava export, with optional TrainerRoad data.

## Setup

```bash
pip install -r requirements.txt
streamlit run app.py
```

## Getting your data

**Strava** (source for distance, elevation, consistency/volume, and workout structure detection):
1. Go to Strava → Settings → My Account → "Download or Delete Your Account" → request a **Bulk Export**.
2. Strava emails you a zip file. This zip can be large (1GB+) once it includes individual activity files — on the Upload Data page, paste the **local file path** to the zip rather than uploading it through the browser. The app reads directly off disk and never loads the whole archive into memory.
3. If you only have `activities.csv` (no individual activity files), that still works for goals/charts, but per-ride workout structure detection needs the full zip (it reads power data out of the gzipped FIT files under `activities/`).

**TrainerRoad** (optional, for FTP history):
TrainerRoad doesn't always let you export full workout history. If you can export a workout history / career CSV, upload it on the Upload Data page for an FTP-over-time chart. If not, just set your current FTP manually on the **Goals** page — everything else works without it.

Uploaded data is parsed and cached locally under `data/` (git-ignored) so you don't need to re-load every time you restart the app.

## Goal types

Configure targets for each on the **Goals** page:

- **FTP / power** — current FTP (manual entry, or from a TrainerRoad export if you have one) vs. a target by a target date.
- **Distance** — target annual mileage, with a projection based on your current year-to-date pace.
- **Elevation / climbing** — target annual elevation gain, same pace projection.
- **Consistency / volume** — target rides per week, tracked as a trailing 4-week average.

## Workout structure detection

On the **Rides Explorer** page, select any ride to see its power stream and a best-effort label of its interval structure (e.g. `5 x 5:00 @ 279W, 3:00 recovery` or `Steady effort @ 150W`). This is inferred from the ride's raw power-vs-time data — it's a heuristic (segments the power stream into work/rest blocks and looks for repeats), not an exact reconstruction of whatever workout was actually prescribed, so treat the label as approximate. Requires the full Strava zip (see above) — no power stream, no detection.

## Training plan

The **Training Plan** page estimates TSS per ride from your power data and current FTP, tracks a rolling 6-week load trend, and flags past weeks where load spiked then crashed (a rough burnout proxy — future ramps are kept gentler if this shows up in your history). It then proposes a 2-week day-by-day schedule (e.g. `Tue: 20 x 0:30`, `Sat: Long endurance ride`) sized to a sensible ramp off your recent load, using your Consistency goal for how many days/week and your ride history for which weekdays and which day is your long ride.

This is a heuristic assistant, not a coach: TSS is estimated (not computed from a real power-duration curve), and "on pace for your FTP goal" is a qualitative read of load trend, not a physiological projection. Requires a current FTP set on the Goals page.

## Design notes

Strava is treated as the source of truth for ride volume, distance, elevation, and power data (it captures both outdoor and synced indoor rides, and its bulk export includes the raw FIT files needed for interval detection). TrainerRoad, if you have an export, only adds FTP history on top of that.

## Sample data

`sample_data/` has synthetic activity/workout CSVs (generated by `scripts/generate_sample_data.py`) so you can try the goal-tracking side of the app without real exports — click "Load sample data" on the Upload Data page. `scripts/build_test_zip.py` is a separate dev-only helper (needs `pip install fit-tool`) that builds a synthetic zip with real FIT files, used to test the workout-detection pipeline — not needed to run the app itself.
